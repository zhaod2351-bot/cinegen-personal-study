# OpenAI 全自动故事板流水线设计

## 目标

为个人学习版补充一条可在本机完整运行的自动 API 流程：使用 GPT 将锁定剧本拆解成结构化制作数据，使用 `gpt-image-2` 生成单张 3×2 六格故事板，并把结果同步回设计与资产、导演工作室及本地中文素材目录。

第一阶段只保证本机端到端走通，不部署公网后端，不接视频生成模型。

## 设计原则

- OpenAI API Key 只能存在于本机服务的环境变量中，不能进入浏览器、Git 仓库、构建产物或项目数据。
- 锁定剧本是角色、场景、道具、Clip、Shot 和故事板的唯一生产来源。
- AI 输出可以被人工修改；重新生成必须创建新版本，不能静默覆盖已完成版本。
- 资产参考图和手填信息优先于模型推断，且在重新分析或重新生成时保留。
- 每个长任务都必须具有可查询的状态、进度、错误信息和重试入口。
- API 服务与 UI 通过稳定的数据契约连接，未来可以将本机服务迁移到云端而不重写前端业务。

## 总体架构

### 本机 Web 应用

本机 Node 服务同时托管构建后的 React 个人版和 `/api`，避免 HTTPS GitHub Pages 调用本机 HTTP 服务时出现混合内容与私有网络访问限制。

开发阶段使用：

- 前端：Vite 开发服务器。
- 后端：独立 Node API 进程。
- Vite 将 `/api` 代理到本机后端。

验证阶段使用：

- Node 服务直接托管 `dist`。
- 浏览器只访问一个本机地址，所有 API 同源。

### OpenAI 接入

- 文本模型通过 `OPENAI_TEXT_MODEL` 配置，不在代码中锁死具体 GPT 型号。
- 图片模型固定为 `gpt-image-2`。
- 服务端使用结构化输出约束文本结果。
- 图片生成输入包含六个镜头、项目画风、连续性约束和可用的角色/场景/道具参考图。

## 数据流

### 剧本分析

1. 用户编辑并锁定剧本。
2. 前端提交剧本正文、项目画风、作品标签、语言、画幅和预估时长。
3. 后端调用 GPT，要求输出严格的 `DirectorPlan`：
   - 润色后的剧本。
   - 角色、场景、道具。
   - Clip 列表。
   - 每个 Clip 的 Shot 列表。
   - Shot 的景别、动作、运镜、时长、对白/环境声、资产绑定和画面提示词。
4. 后端验证引用完整性、类型与唯一性。
5. 前端展示预览；用户确认后写入项目状态并锁定当前生产版本。
6. 同名资产只在类型一致时复用，并保留已有参考图、手填描述、标签和生成状态。

### 故事板生成

1. 用户在导演工作室选择 Clip，点击“生成新版本”。
2. 后端从请求中接收已保存的 Clip、Shot 和引用资产；不重新猜测缺失数据。
3. 提示词构建器生成一份自研导演指令包，结构包括：
   - 角色与任务。
   - 剧情和镜头输入。
   - 角色身份、服装、场景空间、道具和光线连续性规则。
   - 场景拆解、情绪曲线、摄影策略和故事板规划。
   - 3×2 六格固定输出格式。
   - 景别与构图多样性。
   - 禁止字幕、标签、水印和额外文字。
4. 后端创建任务，立即返回 `jobId`。
5. 工作器调用 `gpt-image-2`，生成一张横向六格联系表。
6. 前端轮询任务状态并显示排队、生成中、完成或失败。
7. 完成后创建故事板新版本，写回图片 URL、本地文件路径、生成参数、时间和来源 Shot。
8. 上一版本始终保留，可切换、删除或重新生成。

## API 契约

### `POST /api/director-plans`

创建剧本分析任务。

请求包含项目创作设定与锁定剧本，不包含 API Key。

响应：

```json
{
  "jobId": "job_xxx",
  "status": "queued",
  "progress": 0
}
```

### `POST /api/storyboards`

创建故事板生成任务。

请求包含项目 ID、Clip、Shot、画风和已引用资产。后端验证 Shot 数量；少于六格时按导演规则补充过渡镜头，多于六格时由 GPT 选择六个叙事关键帧，但不修改导演工作室原始 Shot。

### `GET /api/jobs/:jobId`

统一查询文本与图片任务：

```json
{
  "jobId": "job_xxx",
  "kind": "director_plan",
  "status": "in_progress",
  "progress": 35,
  "message": "正在规划镜头",
  "result": null,
  "error": null
}
```

状态固定为 `queued | in_progress | completed | failed`。任务完成前不返回不完整业务结果。

### `POST /api/jobs/:jobId/retry`

使用原输入重新执行失败任务，生成新的尝试记录，但保持同一个业务任务入口。

## 本地存储

任务元数据保存在应用数据目录，服务重启后仍可恢复。生成图片写入：

```text
D:\AI动画创作素材\{项目名}\{场次名}\故事板\v{版本号}\故事板.webp
```

同时写入一个不含密钥的 `生成信息.json`，记录模型名、生成时间、画风、Shot ID、任务 ID 和失败/重试历史。

路径中的非法 Windows 字符由后端统一替换，目录名保持中文。

## 前端改动

- 设置页增加“本机 AI 服务”状态、文本模型和图片模型只读信息。
- 原创剧本页增加自动分析入口和任务进度。
- 导入式剧本继续保留，作为无 API 或人工修正的备用入口。
- 导演工作室的“生成新版本”连接真实任务，不再只创建空版本。
- 故事板面板显示任务进度、错误、重试、版本、图片和本地保存位置。
- 设计与资产自动接收分析出的资产，但不自动生成资产三视图；参考图仍由用户上传。

## 配置与安全

本机 `.env` 至少包含：

```text
OPENAI_API_KEY=
OPENAI_TEXT_MODEL=
OPENAI_IMAGE_MODEL=gpt-image-2
AI_ASSET_ROOT=D:\AI动画创作素材
```

- `.env` 必须被 Git 忽略。
- 日志不得打印请求头、API Key、完整图片 Base64 或用户上传图片。
- 后端只监听回环地址，默认不允许局域网访问。
- 请求体、图片数量、图片大小和并发任务数均设置上限。
- 开发阶段不实现多用户鉴权；云端迁移前必须补充鉴权、配额和持久化对象存储。

## 错误处理

- GPT 输出格式不合法：服务端进行一次格式修复；仍失败则返回可读错误，不修改项目。
- 资产引用缺失或跨类型同名：拒绝写入并指出具体引用。
- OpenAI 限流或临时错误：指数退避，最多三次。
- 图片任务失败：保留上一故事板版本和本次失败记录。
- 本地写盘失败：图片仍返回前端预览，但任务标记为“完成但归档失败”，允许单独重试归档。
- 前端刷新：根据 `jobId` 恢复轮询。

## 测试策略

### 单元测试

- 导演提示词构建器包含六格格式、连续性规则、项目画风和正确的 Shot/资产引用。
- GPT 结构化结果验证、跨类别同名资产和引用缺失校验。
- 任务状态转换、重试与服务重启恢复。
- Windows 中文路径清理与版本目录生成。
- 已存在资产元数据和参考图不会被重新分析覆盖。

### API 集成测试

- 使用依赖注入的假 OpenAI 客户端验证请求与响应，不调用付费接口。
- 验证 API Key 不出现在任何响应或日志中。
- 验证故事板生成完成后写盘并创建版本记录。

### 真实冒烟测试

在用户配置 API Key 后，只执行一次短剧本分析和一次六格图片生成，人工核对：

- 角色与场景连续性。
- 六格叙事顺序。
- 项目画风一致性。
- 导演工作室、设计与资产和故事板版本的同步。
- D 盘中文目录归档。

## 第一阶段完成标准

- 用户无需复制粘贴 ChatGPT 内容即可从锁定剧本生成完整导演数据。
- 用户可以对 AI 结果修改后再生成故事板。
- 一个 Clip 可以生成、查看、切换和重试故事板版本。
- 图片由 `gpt-image-2` 生成并自动保存到 D 盘约定目录。
- API Key 不进入前端和 Git。
- 自动测试全部通过，真实 API 冒烟测试成功一次。

## 暂不包含

- 视频生成。
- 公网后端部署。
- 多用户账号、计费与配额。
- 自动生成角色、场景或道具三视图。
- 对原版 AniKuku 隐藏提示词的逐字复制；个人版使用基于已验证流程结构的自研导演模板。
